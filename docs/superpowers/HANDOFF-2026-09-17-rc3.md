### Standing rules

- **No production write, merge, activation or deploy without the owner saying so**, step by step.
- **Never print a database URL.** Pass it inline: `DATABASE_URL="$(grep '^DATABASE_URL' .env.remote | cut -d= -f2-)"`.
  The repository is public and `.env.*` is gitignored.
- **Ingestion stays frozen** until 48 hours after activation, and only ever runs from this PC, under `.venv313`.
- **Database tests only against `valo_rc3_test`** — never the rehearsal database, which tests that empty tables refuse.
- **Every step asserts its database by name** (`release_preflight.py`, or `--expect-database`).
- **After any interrupted swap or lost connection, run `swap_impact_scores.py state` first.** The log holds a
  `swap swapped` entry exactly when the swap committed.
- The ledger (`2026-09-07-predeclared-values.md`) is append-only: a mistake needs a correction entry, not an edit.

### Traps worth remembering

- `cache_version()` includes `IMPACT_CALCULATION_VERSION`, so prewarm and the coverage check run **from the activation
  checkout**; rows written by any other checkout are ignored by the site.
- The player cache is cleared by **DELETE, never TRUNCATE**: a page load holds its cache read lock while its own second
  connection writes through, and a TRUNCATE between them wedges with no deadlock to break it.
- `lock_timeout` bounds each lock acquisition, not a transaction. The swap makes two.
- Migration 0008–0010 downgrades are DDL only, so R2's downgrade is not refused by the gate. Re-running the gate
  installer below revision 0009 fails, because `round_player_spend` no longer exists; after R2 the gate is lifted
  deliberately with `DROP FUNCTION scoring_gate_guard() CASCADE`.
- Render's build runs only `pip install` and `alembic upgrade head`. It does not load seed data, whatever CLAUDE.md
  says; the seed file would TRUNCATE the score tables, which the gate now refuses anyway.
